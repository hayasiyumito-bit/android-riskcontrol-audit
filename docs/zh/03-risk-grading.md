# 风险分级模型

> 核心公式:**风险等级 = 信号确定性 × 作恶链完整度**。
> 审查一个 App 时,不仅看"检测到什么",更要看"**判罚分级是否合理**"——单信号误判成高危会误伤真人,是常见缺陷。

---

## 三档总原则

| 档 | 判定 | 典型 |
|----|------|------|
| **高(确凿 / 直接判罚)** | 确定性作弊环境,**或**"工具 + 伪装/注入"链条完整 | 云机、模拟器、改机作案、群控作业、Frida注入+伪装 |
| **中(怀疑 / 需人工复核 / 二次校验)** | 有工具/能力,但未形成完整作恶链 | 有 root 不注入、有框架不伪装、单独注入痕迹、多开 |
| **低(仅上报 / 聚类)** | 单点环境异常,开发者/高级用户常见 | 单纯 adb、单纯 VPN/代理、mock 定位、bootloader 解锁 |

口诀:**"环境确定" 或 "工具 + 伪装/注入" → 高;"只有工具" → 中;"只有开关异常" → 低。**

---

## 关键:什么算"确凿高危" vs "只是怀疑"

这是审查里最容易出错的地方。**单独查到一个工具/框架/注入的"存在性",不应直接报高危红**。

### 确凿高危(伪装/篡改的 cross-layer 证据)
- 指纹**跨层交叉不一致**(file/native 层 ≠ Java 层):近乎零误报,最强。
- 属性区真值 ≠ 进程内读 / 属性多通道不一致:主动伪装证据。
- 系统关键文件被 bind-mount 替换(挂载注入):主动伪装机制。
- boot 状态被伪装(getprop 真值 ≠ 进程内)。
- 确认的模拟器/VM/云机(多信号融合,非单传感器)。

### 只是怀疑(工具/框架/注入的"存在性"单信号 → 人工复核,不单独报红)
- 检测到 Hook 框架 / LSPosed / Xposed 类**存在**(未证实伴随伪装)。
- 从 code_cache 热加载的**注入痕迹**(注意:热修复 Tinker/Sophix、加固壳也从数据目录加载,**会误报**,须靠"是不是外来身份"消歧,见下)。
- Root / Magisk / su **存在**,但指纹一致、无注入、无伪装。
- 按名字匹配命中的框架特征(改名即失效)。
- 检测被对抗(except_error / 占位值):WATCH,进人工。

### 为什么"注入存在"默认只算怀疑
从 App 自己的 `code_cache` 加载代码,**合法场景并不罕见**:主流热修复框架(Tinker、Sophix、Robust 等)、插件化框架(RePlugin、Shadow 等)、商用加固壳(把解密后的真 dex 落到数据目录再加载)都会这么做。单看"从 code_cache 加载"无法区分注入与热修复 → **误报**。

**消歧升级为确凿的条件**(排除热修复后):
- 注入物是**异包** APK/类(含不属于本 App 的包名);
- dex 里有 **Xposed 入口**(`IXposedHookLoadPackage` 等);
- 与 sepolicy 检出的 LSPosed 相关联;
- 伴随指纹交叉不符。
满足任一 → 从怀疑升确凿。

## 多信号融合(反单点误伤)

- **任何单一规则都有误报**(定制 ROM、平板、开发者机),用**加权打分 + 阈值**,不单点硬封。
- 文档级规则:**≥2 项中危命中 → 升级为高危 / 触发强验证**。
- 实测教训:传感器异常**单条**精确率仅 ~62%、误伤 ~10% → **严禁单独触发激进动作**(喂假/断网/封禁),只能作为加分项参与组合判定。

---

## 分级 → 响应(承接主动防御)

| 置信档 | 允许的最强响应 |
|--------|--------------|
| **L3 高置信**(注入+伪装 / root+篡改 / 恶意无障碍+聚类) | 喂假数据、关键接口断网、拦截(仅此档) |
| **L2 中置信**(仅 root / 有框架不伪装 / 模拟器单信号 / 多开) | 功能降级、强制服务端二次校验、静默打标 |
| **L1 低置信**(单纯 adb/vpn/proxy/mock / 传感器单条) | 仅静默上报,不做用户侧动作 |

> 激进动作(喂假/断网/拦截)仅 L3 允许,且须可灰度、可一键回滚、可按设备簇精准生效 —— **宁可漏防,不可错杀真人**。

---

## 审查用:分级合理性检查表

- [ ] "检测到 Hook/LSPosed/注入"是否被直接判成高危红?(应为怀疑,除非有伪装佐证)
- [ ] 指纹跨层不一致是否被正确判成高危?
- [ ] 传感器/单环境开关是否被单独用于激进动作?(不应)
- [ ] 是否有"≥2 中危升高危"的累加逻辑?
- [ ] except_error / 占位值是否被无声吞掉?(应进 WATCH)
- [ ] 激进响应是否只在 L3、且可灰度回滚?
