# 设备风控上报参数 · 风险分级文档

> 样本来源：某商用风控 SDK 设备指纹上报（sdkversion 2.2.9）
> 分析目的：梳理各上报字段的判罚价值，划分 **极高风险 / 中等风险 / 低风险（辅助）** 三档，供规则引擎配置参考。

---

## 0. 本样本结论（先看这个）

本样本**已命中极高风险**，核心证据链如下（三条互相印证）：

| 证据 | 字段 | 值 | 说明 |
|---|---|---|---|
| ① Magisk/resetprop | `magisk` | `su\n#resetprop\n#` | 检测到 Magisk 的 `su` 与 `resetprop`，`resetprop` 是篡改系统属性的工具 |
| ② 指纹交叉校验不一致 | `file_*` vs `java_*` | 某 Google 机型/A17 ↔ 某三星机型/A12 | Java 层被伪装成三星，文件/native 层暴露真机是 某 Google 机型 |
| ③ 代码注入 | `injectSoInfo` / `injectDexInfo` | 非空 | 存在注入的 .so / .dex（需进一步确认是否系统合法库，见下） |

> 真机 = 某 Google 机型（Android 17），通过 Magisk `resetprop` 把 `android.os.Build` 伪装成 某三星机型（Android 12）。
> **注意异常点**：尽管上述信号命中，服务端计算字段 `root:0`、`hook:0`、`untrustdevice:0`、`device_tamper_tag:0`、所有 `yongan_*_flag:0` 均为 0 —— 这本身可能说明**判罚规则漏判**或**检测被对抗绕过**，建议复核规则。

## 一、极高风险参数（命中即高危判罚）

这类字段命中通常意味着设备被 **root / Hook / 注入 / 伪装**，可直接进入高危判罚或强验证。

### 1. Root / Magisk 类
| 字段 | 含义 | 判罚逻辑 |
|---|---|---|
| `magisk` | Magisk 特征（su、resetprop、模块等） | **非空即高危**。本样本含 `su`+`resetprop` |
| `root` | Root 状态 | `1` = 已 root，高危 |
| `yongan_root_flag` | 服务端 root 判定 | `1` = 高危 |
| `selinux` | SELinux 状态 | **Permissive/Disabled（关闭）= 高危**；本样本为 `6666`（读取失败/被屏蔽，异常需关注） |

### 2. 指纹交叉校验（本样本主命中项）
> 原理：`java_*` 来自 `android.os.Build`（Java 层，易被 Hook 篡改）；`file_*` / `devicefinger` 来自文件/native（难篡改）。**两者不一致 = 设备伪装。**

| 对比项 | `file_*`（真实） | `java_*`（伪装） | 一致？ |
|---|---|---|---|
| fingerprint | google/tegu...Android17 | samsung/o1s...Android12 | ❌ |
| brand | `google` | `samsung` | ❌ |
| model | `某 Google 机型` | `某三星机型` | ❌ |
| version_release | `17` | `12` | ❌ |
| sdk | `37` | `32` | ❌ |
| manufacturer | `Google` | `samsung` | ❌ |

相关字段：`file_fingerprint`、`java_fingerprint`、`devicefinger`、`file_brand/model/sdk/...`、`java_brand/model/sdk/...`、`modle`、`rom`。**任一核心项交叉不一致即高危。**

### 3. Hook / 注入框架
| 字段 | 含义 | 判罚逻辑 |
|---|---|---|
| `hook` / `hookmethod` / `hook_system` | Hook 框架检测（Frida/Xposed/LSPosed 等） | 非 0 / 非空即高危 |
| `hookFramworkInfo` | Hook 框架详情 | 非空即高危 |
| `MaliciousInjection` | 恶意注入检测 | 本样本 `except_error`（检测抛异常，疑似被对抗，需关注） |
| `injectSoInfo` | 注入的 .so 列表 | 非空需核实（排除系统合法库后判高危） |
| `injectDexInfo` | 注入的 .dex 列表 | 非空需核实 |
| `loadedLibraries` | 已加载 so 列表 | 用于比对异常/注入库 |
| `proc_mounts_java` | /proc/mounts 读取 | 本样本 `except_error`（异常，疑似对抗） |
| `yongan_hook_behavior_flag` / `yongan_ua_hook_flag` / `yongan_copcode_hook_flag` | 服务端 Hook 行为判定 | `1` = 高危 |

### 4. 模拟器 / 虚拟机 / 云手机
| 字段 | 含义 |
|---|---|
| `is_simulator` / `ld_simulator` / `yongan_simulator_flag` | 模拟器判定，`1` = 高危 |
| `VMFile` / `VMSpecialFile2` | 虚拟机特征文件，非空即高危 |
| `cloud_phone` / `cloud_phone_v2` / `yongan_cloud_phone_flag` | 云手机判定，`1` = 高危 |

### 5. 整机篡改 / 不可信
| 字段 | 含义 |
|---|---|
| `untrustdevice` / `untrustclient` | 不可信设备/客户端，`1` = 高危 |
| `device_tamper_tag` | 设备篡改标记，`1` = 高危 |
| `fakeapp` | 应用被篡改/假客户端，`1` = 高危 |
| `appsign` / `signData` | 应用签名校验，签名不符 = 高危 |

## 二、中等风险参数（需结合其他信号或行为联合判定）

单独命中不一定判罚，但叠加其他信号或高频行为时提升风险等级。

| 字段 | 含义 | 风险说明 |
|---|---|---|
| `adbEnabled` | ADB 调试开关 | 本样本 `0`。开启（`1`）= 中风险，开发者/自动化常见 |
| `isUsbAdbConnected` | USB ADB 已连接 | `1` = 中风险 |
| `vpnstatus` / `vpnstatus2` / `yongan_vpn_flag` | VPN | 开启常见于改 IP/地域，中风险 |
| `proxy` | 代理 | 开启 = 中风险 |
| `mockLocation` | 模拟定位 | `1` = 中风险（位置作弊） |
| `accessbilityServiceEnable` / `accessbilityServiceList` | 无障碍服务开关/列表 | 开启可做自动化脚本，中风险 |
| `isEvilAccessibilityService` / `evilaccessibilityServiceDetail` | 恶意无障碍服务 | 命中 = 偏高风险 |
| `duokai` / `duokai_v2` / `yongan_duokai_v3_flag` / `yongan_duokai_tool_flag` / `yongan_duokai_env_flag` | 多开/分身 | 命中 = 中风险（批量养号） |
| `dataDirAccess` | 数据目录可访问 | `1` = 中风险 |
| `build_prop_modified` | build.prop 修改时间 | 本样本 `1230768000000`(=2009 固定值) 疑似伪造，异常可疑 |
| `flashLocked` / `vbmetaDeviceState` / `verifiedBootState` | Bootloader 锁 / Verified Boot | 本样本 locked/green（正常）；unlocked/orange = 中高风险 |
| `abnormal_sensor` / `abnormal_cpu` / `abnormal_rom` / `abnormal_device` | 服务端异常标记 | `1` = 中风险（模拟器/改机常伴随） |
| `sensorInfo` / `gyroscope` | 传感器数据 | 缺失/全 0/固定值 = 可疑（真机罕见） |
| `yongan_auto_tool_flag` | 自动化工具 | `1` = 中风险 |
| `is_abnormal` | 综合异常描述 | 非空需看具体内容 |
| `simstatus` / `simstate` / `simCount` / `abnormal_imei` | SIM/IMEI 异常 | 无 SIM + 其他信号叠加时提升风险 |

## 三、低风险 / 辅助参数（单独不判罚，用于聚合、画像、一机一码）

这些字段多为**设备画像、唯一标识、环境采集、频次统计**，单独无判罚意义，主要用于关联分析、新老设备识别、刷量聚类。

| 分类 | 字段 |
|---|---|
| 设备唯一标识 | `mmuid` `mmuidv1/v2/v3` `drmuid` `android_id` `oaid` `installation_Id` `installTime` `boot_id` `uid` `uid_source` |
| 新设备/聚类标记 | `new_device` `mmuid_new_device` `mmuidv3_new_device` `mmuidx_new_device` `ios_dc_old_device` `log_restart_tag` |
| 刷量频次标记 | `brush_tag` `freq_brush_tag` `brush_tag_48h` `brush_tag_v4` `mainboard_tag` |
| 网络/IP | `nettype` `network_type` `device_ip` `ip` `remote_addr` `x_real_ip` `x_forwarded_for` `mac` `macinfo` `wifi_detail` `wifi_list` `configured_wifi` `ip_country/province/city` `mmdns` |
| 硬件画像 | `screen` `hardware` `cpuabi` `cpuabilist` `cpucount` `cputype` `radioVersion` `bootserialno` `devicename` `hostname` |
| 应用/环境 | `installed_packages` `packageName` `appname` `version_code/name` `buildnumber` `default_input_method` `input_methods` `user_agent` `cmdline` |
| 运行状态 | `elapsedRealtime` `bootTime` `start_time` `firstInstallTime/firstRunTime/lastUpdateTime` `*Volume`(各音量) `storageDetail` `inputDevice` `photo_count` `isDeviceSecure` `isBiometricSupported` |
| 文件探测 | `file_stat`（各路径 inode/时间，用于交叉核对真实性） |
| 业务标识 | `accountid` `sessionid` `channel` `source` `client` `drmuid` |

> 说明：低风险字段中若出现**大量 `6666` 占位值**（如 `imei/imsi/macinfo/oaid/cid/cputype/hostname/selinux/storageDetail`），通常表示该信息被系统限制或被主动屏蔽；**大面积屏蔽本身可作为一个弱可疑信号**参与综合评分。

## 四、规则引擎建议（判罚优先级）

```
高危直接判罚（任一命中）：
  magisk 非空 | root=1 | selinux=Permissive
  | 指纹交叉不一致(file_* ≠ java_*)
  | hook/hookmethod/hook_system 命中 | VMFile 非空
  | is_simulator=1 | untrustdevice=1 | device_tamper_tag=1 | fakeapp=1

中危（≥2 项命中升级为高危 / 触发强验证）：
  adbEnabled | isUsbAdbConnected | vpnstatus | proxy | mockLocation
  | 无障碍恶意服务 | duokai* | bootloader unlocked
  | abnormal_sensor/cpu/rom | build_prop_modified 异常

低危：仅用于设备聚类、一机一码、刷量关联，不单独判罚。

额外可疑信号（建议加分）：
  检测字段返回 except_error（如 MaliciousInjection / proc_mounts_java）
  | 核心字段大面积 6666 屏蔽
  | 服务端 flag 全 0 但原始信号命中（疑似漏判/对抗，需复核）
```
