# 设备风控规则分级（按作弊维度 · 完整版）

> 样本：某商用风控 SDK 设备指纹上报
> 核心思路：**风险等级 = 信号确定性 × 作恶链完整度**。同一设备可同时命中多个维度。
> 字段标注：`[已采集]` = 当前 payload 已有字段；`[建议补采]` = 业界常用但本 payload 未见，建议 SDK 增加。
> 说明：下列规则综合业界公开检测手段整理（来源见文末）。单一信号误报率高，**务必多信号融合评分**。

---

## 一、分级总原则

| 等级 | 判定逻辑 | 典型 |
|---|---|---|
| **高** | 确定性作弊环境，或"环境 + 伪装/注入"链条完整 | 云机、模拟器、改机作案、群控作业、主板翻新改串、Frida注入+伪装 |
| **中** | 有工具/能力，但未形成完整作恶链 | 有 root 不注入、有框架不伪装、多开、无障碍开启、VPN+代理叠加 |
| **低** | 单点环境异常，开发者/高级用户常见 | 单纯 adb、单纯 VPN/代理、mock 定位、数据目录可访问 |

> 口诀：**"环境确定" 或 "工具 + 伪装/注入" → 高；"只有工具" → 中；"只有开关异常" → 低。**
> 补充评分项（WATCH）：检测抛异常、核心字段大面积屏蔽、原始信号命中但服务端标签全 0 → 疑似对抗/漏判，进人工。

---

## 二、维度详解

### 1. 云机（Cloud Phone / redroid / Docker-ARM）
> 本质：无真实机身的容器化 Android，跑在 ARM 服务器（Ampere/Graviton 等）上，用 Docker/redroid 部署，共享宿主内核。**最强判据是"没有硬件"——传感器、基带、电池、摄像头全缺或恒定。**

| 等级 | 规则 | 字段 |
|---|---|---|
| **高** | 云机标记直接命中 | `cloud_phone` / `cloud_phone_v2` / `yongan_cloud_phone_flag` =1 `[已采集]` |
| **高** | 物理传感器缺失/全 0/长期零波动（无机身） | `sensorInfo` 缺传感器、`gyroscope` 恒定、`abnormal_sensor=1` `[已采集]`；加速度/磁力/光线/**气压**缺失 `[建议补采]` |
| **高** | 无基带/无 SIM 硬件 + radio 异常 | `radioVersion="unknown"` `[已采集]`、`simstate=ABSENT` + 无基带 |
| **高** | GPU 为软件渲染（容器无真实 GPU） | GL_RENDERER 含 **SwiftShader / LLVMpipe / VirGL / virtio_gpu**；`loadedLibraries` 含 swiftshader `[建议补采 GL_RENDERER/GL_VENDOR]` |
| **高** | 容器/Docker 痕迹 | `/proc/1/cgroup` 含 docker、overlayfs 挂载、binder/ashmem 异常加载、`ro.kernel.qemu` 存在（redroid 带该前缀属性） `[建议补采]` |
| **高** | CPU 为服务器芯片跑移动应用 | `/proc/cpuinfo` 现 Ampere Altra / AWS Graviton / Xeon / EPYC `[建议补采 cpuinfo 原文]` |
| **中** | 传感器存在但数值可疑（机械规律/多次上报一致） | `gyroscope` 多次完全相同 |

> 本样本：`sensorInfo:"G1$T1$L1$A1$M1$D1$..."`（陀螺/温度/光线/加速度/磁力俱全）、`gyroscope` 有非零浮点、`cloud_phone=0`、GPU 未见软渲 → **非云机**。
> ⚠️ 注意 `radioVersion="unknown"` 单独看是弱信号（部分真机也如此），本样本因其它硬件齐全不升级。

---

### 2. 模拟器（Emulator / QEMU / VM）
> 本质：QEMU/Goldfish/Ranchu 或 x86 虚拟机。**特征是"大量明显参数异常"**——属性、文件节点、CPU 架构、标识占位值。

| 等级 | 规则 | 字段 |
|---|---|---|
| **高** | 模拟器标记命中 / VM 特征文件存在 | `is_simulator` / `ld_simulator` / `yongan_simulator_flag` =1、`VMFile` / `VMSpecialFile2` 非空 `[已采集]` |
| **高** | 明显模拟器属性 | `ro.kernel.qemu=1`、`ro.hardware`=goldfish/ranchu/vbox、`ro.product.model` 含 sdk_gphone / "Android SDK built for x86"、`ro.bootloader=unknown` `[建议补采 getprop]` |
| **高** | 模拟器专属设备节点/管道 | `/dev/qemu_pipe`、`/dev/socket/qemud`、`/dev/socket/genyd`、`/dev/socket/baseband_genyd`(Genymotion)、`/data/bluestacks.prop`(BlueStacks) `[建议补采 file_stat 扩展]` |
| **高** | CPU 架构异常：x86 跑 ARM + 翻译层 | `cpuabilist`/`java_abilist` 以 x86 优先、含 **libhoudini / libndk_translation** `[已采集 abilist；建议补采翻译层检测]` |
| **高** | 标识占位值（模拟器返回全 0/固定） | `getDeviceId`=00000000000000、android_id 固定、`abnormal_cpu=1`/`abnormal_rom=1` `[已采集 abnormal_*]` |
| **中** | 硬件特征部分可疑（board/platform 冲突） | `ro.product.board` 与 `ro.board.platform` 不一致、`cputype`/`hardware` 异常 |

> 本样本：`is_simulator=0`、`VMFile=""`、`cpuabilist="arm64-v8a,armeabi-v7a,armeabi"`（纯 ARM）、`abnormal_cpu=0`、`abnormal_rom=0` → **非模拟器**。

---

### 3. 改机 / 指纹伪装（Device Tampering）
> 本质：root/Magisk + `resetprop` 篡改系统属性，把 Java 层 `Build` 伪装成另一机型。**最强判据是"交叉校验对不上"**——Java 层（易篡改）vs 文件/Native 层（难篡改）。

| 等级 | 规则 | 字段 |
|---|---|---|
| **高** | 指纹交叉不一致（Java 被伪装） | `file_* ≠ java_*`：brand/model/sdk/version/fingerprint 任一核心项不符 `[已采集]` |
| **高** | root/Magisk + 正在改属性 | `magisk` 非空且含 `resetprop`；`device_tamper_tag=1`、`untrustdevice=1` `[已采集]` |
| **高** | SELinux 关闭 + 改机工具 | `selinux`=Permissive/Disabled + `magisk`/`root` `[已采集]` |
| **中** | 有 root/Magisk，但指纹一致、无注入、无伪装 | `root=1` 或 `magisk` 非空，且 `file_*==java_*`、`injectSoInfo` 空 |
| **中** | build.prop 被改 / 调试属性异常 | `build_prop_modified` 异常（如固定 `1230768000000`=2009）、`ro.debuggable=1`、`ro.build.tags=test-keys`、`ro.adb.secure=0` `[已采集 build_prop_modified；建议补采 getprop]` |
| **中** | Native 读取的 fingerprint 与 Java 层不符 | `Build.FINGERPRINT` vs `ro.build.fingerprint`(native) |
| **低** | Bootloader 解锁但无其它改动 | `flashLocked=0`、`vbmetaDeviceState=unlocked`、`verifiedBootState=orange/yellow` `[已采集]` |

> 本样本 ✅ **高风险命中**：`magisk="su #resetprop #"` 且 `file_*`(Google/某 Google 机型/A17/sdk37) ≠ `java_*`(samsung/某三星机型/A12/sdk32)。真机 某 Google 机型 被 resetprop 伪装成某三星机型。

---

### 4. Root / Magisk / Zygisk（常与改机叠加）
> Shamiko/DenyList 隐藏改变的是"应用看到什么"而非系统实际状态，**检测应转向行为、元数据、命名空间一致性**。

| 等级 | 规则 | 字段 |
|---|---|---|
| **高** | root + 作恶（注入/伪装，见 §3/§5） | `root=1`/`magisk` 非空 + 其它高危 `[已采集]` |
| **高** | mount/namespace 痕迹（Shamiko 下仍有效） | `/proc/self/mountinfo` 含 magisk、`/proc/self/attr/prev` 含 zygote(zygisk)、mount/PID namespace 不一致 `[建议补采]` |
| **中** | 仅 root，无伪装无注入 | `root=1` 或 `magisk` 非空单独出现 |
| **低** | SELinux permissive 单点 | `selinux` 异常单点 |
| 参考 | 硬件背书完整性（最强，难软件绕过） | Play Integrity `MEETS_STRONG_INTEGRITY` `[建议接入]` |

---

### 5. Hook / 代码注入（Frida / Xposed / LSPosed）
> 判定核心：**框架存在 + 是否注入 .so/.dex + 是否伪装业务**。三者齐全=高，仅框架=中。

| 等级 | 规则 | 字段 |
|---|---|---|
| **高** | 框架 + 注入非应用路径 .so/.dex + 伪装 | `hook`/`hookmethod`/`hook_system` 命中 + `injectSoInfo`/`injectDexInfo` 非系统库 + `yongan_hook_behavior_flag`/`yongan_ua_hook_flag`/`yongan_copcode_hook_flag=1` `[已采集]` |
| **高** | `/proc/self/maps` 现框架特征串 | 含 "frida" / "xposed" / "gum-js-loop" / "gmain" / "LSPosed" `[建议补采 maps 扫描]` |
| **高** | Frida 端口/文件 | `/proc/net/tcp` 含 **27042/27043**、`/data/local/tmp/re.frida.server` `[建议补采]` |
| **高** | 非应用路径映射可执行 .so（dirty page/inline hook） | `loadedLibraries` 现未知路径 .so `[已采集 loadedLibraries]` |
| **中** | 检测到框架但无伪装/业务注入 | `hookFramworkInfo` 非空但指纹一致、UA 未改 |
| **WATCH** | 检测抛异常（疑似对抗绕过） | `MaliciousInjection="except_error"`、`proc_mounts_java="except_error"` `[已采集]` |

> 本样本：`injectSoInfo`/`injectDexInfo` 非空（路径含 gms/webview，需确认是否系统合法库），但 `hook=0`/`hook_system=0`/`yongan_*=0`，且 `MaliciousInjection`/`proc_mounts_java` 返回 `except_error` → **检测对抗/漏判嫌疑，强制人工复核**。

---

### 6. 群控（Device Farm / 自动化控制）
> 判定核心：**自动化输入（adb/无障碍）+ 通信通道（socket/ADB-TCP）+ 多设备聚类**。注意 adb keyevent 本身是合法测试命令，须结合行为与聚类定性。

| 等级 | 规则 | 字段 |
|---|---|---|
| **高** | 恶意无障碍自动化 + 批量聚类 | `isEvilAccessibilityService=1`、`evilaccessibilityServiceDetail` 非空、`yongan_auto_tool_flag=1` + 同 IP/高频 `brush_tag`/`freq_brush_tag`/`brush_tag_48h` `[已采集]` |
| **高** | ADB 注入输入事件（模拟点击/keyevent） | `inputDevice` 现异常 virtual 输入源 + 自动化行为 `[已采集 inputDevice]`；ADB-TCP：`/proc/net/tcp` **5555** 已建立连接 `[建议补采]` |
| **高** | 群控 socket 通信（复占端口可探测） | 已知群控端口被占用/监听 `[建议补采端口探测]` |
| **中** | 无障碍服务开启（非已知恶意）/ ADB 自动化就绪 | `accessbilityServiceEnable=1`、`accessbilityServiceList` 非空、`isUsbAdbConnected=1`、`ro.debuggable=1`/`ro.adb.secure=0` `[已采集部分]` |
| **中** | 控件树 dump 行为（时效性差但可参考） | 无障碍频繁 dump |
| **低** | 单纯刷量频次偏高，无自动化证据 | `brush_tag=1` 单独出现 |

> 本样本：`accessibility=[]`、`isEvilAccessibilityService=0`、`inputDevice` 全为物理设备（gpio_keys/goodix_fingerprint/synaptics_touch）、`brush_tag=0` → **无群控证据**。

---

### 7. 主板 / 翻新机 / 改串 / 一机多号
> 本质：同一物理主板反复抹机、改 IMEI/SN、恢复出厂来重置设备身份批量养号。**判据是串码一致性 + 频繁新设备 + 多账号聚类。**

| 等级 | 规则 | 字段 |
|---|---|---|
| **高** | 主板标记 + 串号/标识异常或清零 | `mainboard_tag=1` + (`abnormal_imei=1`/`abnormal_android_id=1`/`android_id_zero=1`/`bootserialno` 异常) `[已采集]` |
| **高** | 同主板短期频繁"新设备"（抹机刷身份） | `mainboard_tag` 稳定但 `new_device`/`mmuid_new_device`/`mmuidv3_new_device` 频繁置 1 `[已采集]` |
| **高** | 一机多号（同设备绑大量账号） | 同 `mmuid`/`mmuidv3` 关联多 `accountid`（图谱关联） `[服务端聚合]` |
| **中** | 三码/硬件不一致（IMEI vs SN vs 主板） | `abnormal_imei=1` 或 `abnormal_android_id=1` 单点；传感器校准偏差异常 `[部分已采集]` |
| **中** | 恢复出厂导致指纹漂移 | 短期 android_id/标识变更频繁 |
| **低** | 单纯首次新设备上报 | `new_device=1` 首登 |

> 本样本：`mainboard_tag=0`、`abnormal_imei=0`、`abnormal_android_id=0`、`android_id_zero=0`、`duokai=0`；`new_device=1` 为首登 → **无主板翻新证据**。

---

### 8. 多开 / 分身
| 等级 | 规则 | 字段 |
|---|---|---|
| **高** | 多开 + 假客户端/注入 | `duokai*=1` + `fakeapp=1` `[已采集]` |
| **中** | 多开/分身环境 | `duokai`/`duokai_v2`/`yongan_duokai_v3_flag`/`yongan_duokai_tool_flag`/`yongan_duokai_env_flag=1`、`virtualpath` 路径异常 `[已采集]` |

> 本样本：`duokai*=0`、`fakeapp="0"`、`virtualpath` 为正常私有目录 → **无多开**。

---

### 9. 位置 / IP / 网络环境
| 等级 | 规则 | 字段 |
|---|---|---|
| **中** | IP 归属地 ↔ 时区 ↔ GPS 三者不一致 | `ip_country/province/city` vs `lat`/`lon` vs 系统时区 `[已采集]` |
| **中** | 模拟定位 + 其它作弊叠加 | `mockLocation=1` |
| **低** | 单纯 VPN / 代理 | `vpnstatus`/`vpnstatus2`/`proxy`/`yongan_vpn_flag` |

> 本样本：`mockLocation=0`、`vpnstatus=0`、`proxy=0`、IP 为内网 172.18.x（归属地为空）→ 无位置作弊，但内网 IP 本身可留意。

---

### 10. 环境异常（低风险为主，叠加才升级）
| 等级 | 规则 | 字段 |
|---|---|---|
| **低** | ADB / USB 调试 | `adbEnabled=1`、`isUsbAdbConnected=1` `[已采集]` |
| **低** | 数据目录可访问 | `dataDirAccess=1` |
| **中** | 上述环境项 ≥2 叠加，或配合任一高危维度 | 组合命中 |

## 三、本样本命中总结（多维命中）

| 维度 | 命中 | 等级 | 依据 |
|---|---|---|---|
| **改机/指纹伪装** | ✅ | **高** | `magisk`(resetprop) + `file_*(某 Google 机型) ≠ java_*(某三星机型)` |
| **Root** | ✅ | 高（叠加改机） | `magisk` 非空 |
| **Hook/注入** | ⚠️ 存疑 | WATCH | `injectSoInfo/injectDexInfo` 非空、检测 `except_error`、服务端 flag 全 0 |
| 云机 | ❌ | — | 传感器齐全、GPU 非软渲 |
| 模拟器 | ❌ | — | `is_simulator=0`、纯 ARM、`VMFile` 空 |
| 群控 | ❌ | — | 无障碍空、输入设备物理、`brush_tag=0` |
| 主板翻新 | ❌ | — | `mainboard_tag=0`、串号正常 |
| 多开 | ❌ | — | `duokai*=0` |
| 位置/环境 | ❌/低 | 低 | adb/vpn/proxy/mock 均 0，内网 IP |

> **综合结论：高风险（改机作案，某 Google 机型 伪装成某三星机型）。**
> **关键告警**：原始信号命中改机，但服务端 `root/hook/device_tamper_tag/yongan_*` 标签全为 0，且 `MaliciousInjection`/`proc_mounts_java` 检测抛异常 → **强烈怀疑检测被对抗或规则链漏判**，建议最高优先级核查。

## 五、判罚伪代码

```python
# ===== 高风险：确定环境 OR 工具+伪装/注入链完整 =====
HIGH = any([
    # 云机
    无传感器 or 无基带 or 软件GPU or 容器痕迹 or cloud_phone,
    # 模拟器
    is_simulator or VMFile or qemu属性 or qemu节点 or (x86优先 and 有ARM翻译层),
    # 改机作案
    (root or magisk含resetprop) and 指纹交叉不一致,
    selinux关闭 and (root or magisk),
    # Hook 作恶
    hook_framework and (inject_so非系统库 or 指纹伪装 or ua_hook) ,
    maps含frida_xposed or frida端口27042,
    # 群控
    恶意无障碍 and 设备聚类,
    adb注入输入 and 多设备同节奏,
    # 主板翻新
    mainboard_tag and (改串 or 频繁新设备 or 一机多号),
    # 多开 / 服务端定判
    (duokai and fakeapp) or device_tamper_tag or untrustdevice,
])

# ===== 中风险：有工具/能力，无完整作恶链 =====
MID = any([
    (root or magisk) and not (inject or 指纹伪装),      # 只 root 不作恶
    hook_framework and not 伪装,                         # 有框架不伪装
    duokai,                                             # 多开环境
    开无障碍 or isUsbAdbConnected,                       # 自动化就绪
    env_count(adb, vpn, proxy, mock, dataDir) >= 2,    # 环境异常叠加
    abnormal_imei or abnormal_android_id,              # 串码单点异常
    build_prop_modified异常 or ro_debuggable,          # 属性被改
    IP与时区GPS不一致,                                  # 位置弱异常
])

# ===== 低风险：单点环境开关 =====
LOW = any([adbEnabled, vpnstatus, proxy, mockLocation, dataDirAccess])

# ===== WATCH：不直接判罚，进人工/加分 =====
WATCH = any([
    检测字段 == "except_error",        # 对抗嫌疑（MaliciousInjection / proc_mounts_java）
    核心字段大面积 == "6666",           # 信息屏蔽
    原始信号命中 and 服务端flag全0,     # 漏判嫌疑
])
```

## 六、落地建议

1. **多信号融合评分**：任何单一规则都有误报（真机定制 ROM、Wi-Fi 平板、开发者机），用加权打分 + 阈值，而非单点硬封。
2. **交叉校验优先**：Java 层 vs Native/文件层（指纹、属性、串码）是性价比最高、最难绕过的判据，本样本正是靠它定性。
3. **补采建议字段**：`getprop` 原文、`GL_RENDERER/GL_VENDOR`、`/proc/self/maps` 扫描、`/proc/net/tcp`（27042/5555）、`/proc/self/mountinfo`、`/proc/1/cgroup`、`/proc/cpuinfo` 原文、CPU 翻译层检测、Play Integrity 裁决。
4. **监控检测自身健康**：`except_error` 批量上升 = 对抗升级或采集逻辑崩，应单独告警。
5. **服务端行为补强**：客户端检测必被绕过，须叠加服务端操作节奏、设备-账号关联图谱、位置一致性做兜底。
